# 「キャッチボール → 野球チーム」ファネルの設計と計測

最終更新: 2026-09-13

公園マップ（キャッチボールできる公園）とチームマップ（野球チーム）を1ページに統合するのではなく、
**2ページのまま、利用者の行動の流れが途切れないように相互の導線を張る**方針。
ねらいは「公園でキャッチボールしている親子」を「近くの少年野球チームへの見学・体験」へつなぐこと。

## ファネルの段階と接点

| 段階 | 利用者の状態 | マップ上の接点 |
|---|---|---|
| 1 探す | キャッチボールできる公園を探す | 公園マップ（公認バッジ・地域コンテンツ） |
| 2 知る | 近くに少年野球チームがあると知る | 下記の「プッシュ露出」3か所 |
| 3 興味 | チームの活動場所・連絡先を見る | チームマップのポップアップ（公園から直接開く） |
| 4 体験 | 見学・体験会に申し込む | チームのSNS/HP、地域コンテンツの体験会情報 |

## プッシュ露出（興味がない人にも届く接点）

探しに行った人だけが見る導線では、野球に興味がない層に届かない。そこで**利用者が別の目的で行動したときに自動で目に入る**接点を置く。

1. **地域カード（自動表示）** — 地図で市町村に入った時／公園の詳細を閉じた時に左下へ出るカードに、
   「○○市の少年野球チーム Nチーム（近く：チーム名）」の行を常に入れる。地域コンテンツの掲載がない市でも出る。
   頻度: 同じ市は1セッション1回・1セッション2回まで（既存ルール）、チーム行は×で閉じてから7日間は出さない。
2. **公園モーダル** — キャッチボール可否の直下に「この公園から4km以内に少年野球チームがNチーム」、
   下部に近い順3チームのブロック（タップでチームマップのポップアップが開く）。0件でも「周辺を見る」導線は残す。
3. **投票完了** — 👍/👎投票の直後に「キャッチボールの次は野球チームへ！近くの少年野球チーム：○○」。
   この公園で実際にキャッチボールした人＝最も有望な層に、行動を終えた瞬間に見せる。

逆方向（チーム → 公園）: チームのポップアップに「近くのキャッチボールできる公園」（3km以内・2件）。
活動場所の実座標を持つチームのみ（市の代表座標から「近く」を出すと別地域の公園を案内してしまうため）。

ヘッダーの相互リンク（公園マップ⇔チームマップ）は、押した時点の地図の位置を引き継ぐ。

## データ

- `data/teams-lite.js` — 少年野球チームのうち活動場所の実座標を持つもの（2026-09-13時点 500件）。
  `node scripts/build-teams-lite.js` で `data/teams-data.js` と `js/team-map.js` の `PLACE_COORDS` から生成する。
  **チームデータや活動場所座標を更新したら再生成してコミットする。**

## 計測（GA4）

既存の `list_item_click` イベントを `list_type` で区別して使う（新規イベント定義は不要）。

| list_type | 意味 |
|---|---|
| `xteam_teaser` | 公園モーダル上部「4km以内にNチーム」のタップ |
| `xteam_modal` | 公園モーダル内のチーム行のタップ |
| `xteam_modal_more` | 「チームマップでこの周辺を見る」のタップ |
| `xteam_vote` | 投票完了メッセージのチームリンクのタップ |
| `xteam_splash` | 地域カードのチーム行のタップ |
| `xpark_popup` | チームポップアップ内の公園リンクのタップ |

月次で見る転換の目安:
`modal_open(park_detail)` → `list_item_click(xteam_*)` → チームマップ側の `external_link`（SNS/HP）。
露出面ごとのタップ数を比べ、効かない面は文言・位置を見直す。
